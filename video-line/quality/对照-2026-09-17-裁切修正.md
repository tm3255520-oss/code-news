# 改动前后对照 #1 —— `motion_check.py` 内容区裁切修正

> 日期：2026-09-17｜改动：`scripts/motion_check.py`（指纹 `F8FE70B613FC5B1B` → 见冻结资产文档当前值）
> 测量器：`scripts/card_quality_check.py`（新裁切走它；旧裁切用 1:1 复刻脚本单独跑）

## 一、为什么要做对照

改机器的目的是让片子变好，不是让数字变好看。所以每次改完都要回答同一个问题：
**这次改动到底动了什么，动对了没有。** 没有对照，任何改动都只是"感觉变好了"。

这次的改动不是改片子，是**改尺子**——旧尺子本身是坏的，所以对照的形态是：
同三条片子、同一套判据（10fps / 阈值 0.35）、同一个内容区概念，**只差采样实现**。

## 二、方法

1. 用 1:1 复刻的旧实现（把内容区原图像素除以缩略图比例后去切原图数组）跑一遍；
2. 用修正后的 `motion_check.load()`（按画幅取内容区矩形 → 原图矩形裁切 → 等比缩放）跑一遍；
3. 两条都取 10fps 抽帧、阈值 0.35，逐帧灰度平均绝对差。

## 三、结果

| 片子 | 版本 | 静止率 | 最长静止 | 帧间均值 | 采样帧 |
|---|---|---|---|---|---|
| 横屏基准（1440×1080, 27.8s） | 旧裁切 | 0.888 | 8.30s | 0.559 | 278 |
| 横屏基准 | **新裁切** | **0.292** | **2.10s** | 1.346 | 278 |
| 竖屏基准（1080×1920, 27.8s） | 旧裁切 | 0.968 | 18.60s | 0.775 | 278 |

| 早期 demo（1440×1080, 45.6s） | 旧裁切 | **0.000** | **0.00s** | 1.961 | 456 |
| 早期 demo | **新裁切** | **0.464** | **0.50s** | 0.695 | 456 |

## 四、三条结论

**1. 旧读数不是"有偏差"，是方向都反了。**
demo 那条旧实现报「静止率 0.000、最长静止 0.00s」——读作"全程都在动"；
修正后是「0.464 / 0.50s」——**它其实是三条里最静止的一条**。
旧读数会把人往完全相反的方向带。

**2. 旧标定的出处被坐实了。**
冻结资产文档校准表里那行「我们旧版(卡片) 帧间均值 1.993 静止 0.0% 最长 0.00s」
与本表「demo 旧裁切 1.961 / 0.000 / 0.00」对得上——**那张表就是这套坏代码跑出来的**。
同一张表里的「对标 C 98.7% / D 99.2%」同理，**全部作废，需按新实现重测**。

**3. 同源成片的两画幅必须读数一致，现在一致了。**
横竖两条基准同一份分镜、同一份 `script.json`、同一条音轨，只有画布不同：

| | 修前 | 修后 |
|---|---|---|
| 横屏 静止率 / 最长静止 | 0.888 / 8.30s | 0.292 / 2.10s |
| 竖屏 静止率 / 最长静止 | 0.968 / 18.60s | **0.285 / 2.10s** |
| 两者一致性 | 差一倍（不可能） | 差 0.7%（应当如此） |

这条一致性就是本次改动的**验收判据**。

## 五、由这次对照得出的判断（见「卡片形态要不要继续豁免」）

三条片子在修后的读数上表现出**两种不同的形态**：

| | 静止率（≤40%） | 最长静止（≤1.0s） |
|---|---|---|
| 横屏/竖屏基准 | 0.29 ✅ | 2.10s ❌ |
| demo | 0.46 ❌ | 0.50s ✅ |

**没有一条同时满足 MG 的两个判据，而且各自违反的是不同的那一项。**
这说明 MG 的那对阈值（借自 Remotion 动效项目）在形状上就不适配卡片形态，
不是"松一点紧一点"的问题。故：`--style card` 继续只报告，
但理由从「实测证明卡片本来就静止」改成「**卡片形态我们还没有自有判据**」；
门槛要从我们自己积累的分布里标定，不能继续借用 MG 的数。

死区定位（`motion_check` 新增输出）让这条结论可行动：
横屏/竖屏基准的死区都在**第 4 张卡**（10.59–13.58s）里的 11.40–13.50s，
该段帧间变化恒为 `0.000`（像素完全不变）。
