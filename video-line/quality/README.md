# 质量自检线（本地产出，不入库）

这一目录放**质量自检的历史记录**。测量器在 `scripts/card_quality_check.py`。

## 它是什么，不是什么

它把一条已成片的卡片视频，用**产物自带的证据**算成一张「质量自检卡」。
不渲片、不改模板、不联网、不花钱。

它**不是**完整评分。外部付费拆解服务的六维里，有两维必须靠「外面的眼睛」：

| 维度 | 本线能否自算 |
|---|---|
| Hook（前 3 秒） | ✅ 字幕时间轴 |
| 信息密度 | ✅ 字幕 + 信息单元 |
| 节奏控制 | ✅ 卡片时长 + motion_check |
| 转化引导 | ✅ 末卡文本 |
| 画幅适配 | ✅ 分辨率 vs 声明 vs 平台（**外部服务的六维里没有这一项**） |
| 产品展示 | ❌ 标记 `external_pending`，不假装能算 |
| 情绪曲线 | ❌ 同上 |

## 门槛纪律（重要）

每一行都带「门槛来源」，分三档，**不许把判断值写成实测值**：

- **实测锚点** —— 有实测数字可对（如对标片 C 静止率 98.7%）
- **建议区间 / 推导值** —— 我们的判断，不是实测，会随基线积累被替换
- **待标定** —— 还没有任何依据，只报数不判

硬判据只有三条（不需要任何外部知识）：画幅声明与实际不符、卡片时间轴有缝或重叠、
竖屏平台配横屏成片。其余一律只报告。

## 怎么跑

```powershell
cd C:\Users\Administrator\Documents\code-news

# 人读版（默认追加一条进 history.jsonl）
python scripts\card_quality_check.py video-line\acceptance\vertical --platform 视频号

# 机器可读 / 不记历史
python scripts\card_quality_check.py <产物目录> --platform 视频号 --json --no-record
```

`<产物目录>` 要有 `deck.json`（也兼容旧的 `cards.json`）；有 `final.mp4` 才算画面侧指标；
有 `script.json` 才能取到叙事角色。

退出码：`0` 无硬失败 ／ `2` 输入缺失 ／ `3` 硬失败。

## 自检线自己查出来的东西

1. **【已修 2026-09-16】`motion_check.py` 的内容区裁切曾经是错的。**
   旧实现把内容区原图像素除以缩略图比例后去切**原图数组**，等于只采样原图左上角
   一条窄带（横屏实测 x13–306 / y25–143），根本不是内容区。后果不是小偏差而是结论反转：

   | | 静止率 | 帧间均值 |
   |---|---|---|
   | 旧实现 | 0.888 | 0.559 |
   | 修正后 | 0.292 | 1.346 |

   而且竖屏与横屏同源片读数能差出一倍（96.8% vs 88.8%），**同源成片读数本来就该一致**——
   这就是当初发现它的线索。修法：内容区矩形改从生成器几何派生
   （横屏 `STYLES["grid-dark"].card_inset`、竖屏 `FORMATS["vertical"].geom["card_inset"]`），
   采样改成「按原图矩形裁 → 再等比缩」，分辨率不在表内直接拒绝出结论。
   `tests/scripts/test_motion_check_crop.py` 守着不漂移。

2. **旧标定全部作废，需要重测。** 冻结资产文档里的
   「我们新版静止率 75.1%」「对标 C 98.7% / D 99.2%」都是在旧裁切下测的，与现在不可比。
   **结论方向都可能反**：demo 那条旧实现报「静止率 0.000（全程在动）」，修后是 0.464
   （三条里最静止）。完整对照见 [对照-2026-09-17-裁切修正.md](对照-2026-09-17-裁切修正.md)。

3. **卡片形态该不该豁免 MG 判据 —— 已定：继续只报告，但理由换了。**
   修后三条片子各违反**不同**的一项：横竖基准静止率 0.29 合格、最长静止 2.10s 超标；
   demo 反过来（0.46 超标、0.50s 合格）。**没有一条同时过，且违反项不同**——
   说明 MG 那对阈值在形状上不适配卡片，不是松紧问题。
   故 `--style card` 继续只报告，但依据从「实测证明卡片本来就静止」改成
   「**卡片形态我们还没有自有判据**」；门槛要从自己的分布里标定，不再借 MG 的数。

4. **每卡死区不匀（2026-09-17 新增指标查出来的）。**
   把「最长静止」拆到每张卡上，按序是 0.0 / 0.0 / 1.2 / **2.1** / 0.0 / 1.2 / 1.3 / 0.1 秒。
   **成因不是某一卡，而是动效动词铺不满卡长**：

   | 动词 | 死区 |
   |---|---|
   | `SLAMS 标题` / `SLIDES 标题` | 0.0s（铺满） |
   | `FLOATS 标题` | 2.1s / 1.2s |
   | `TYPES 标题` | 1.2s |
   | `RISES 标题` | 1.3s |
   | `… → FLOATS 卡片`（两目标） | 0.0s（铺满） |

   两点判断：**① 极差（2.10s）比绝对值更该盯**——同一片内忽长忽短就是节奏不匀，
   这与已知缺口「成片偏短、密度靠压时间换」同源；**② 2.1s 这个绝对值暂时不判**，
   因为「卡片形态静止多久算缺陷」我们还没有参照，拿 MG 的 1.0s 判它等于又用那把不合形的尺子。
   可修方向：模板层让各动词时长自适应卡长（`build_card_deck.py`，需走冻结资产改动纪律），
   或分镜层避开"铺不满"的动词单用。
5. **两条基准成片的末卡都没有 CTA**（末卡是结论句）。
   本地自检线判「末卡是否含 CTA = 否」，**外部检测独立给出同一结论**（转化引导 2/10，全片最低分，
   理由「完全缺失转化引导设计」）。两把独立尺子指向同一处——这是目前最便宜的改进项。
   但要不要加、加什么，属于「判断层」的事（分镜技能），不是渲染器能修的。

## 外部检测（第一份：我们的竖屏基准，2026-09-17）

用外部付费拆解服务（`lingyi-wx-video-decomposer-plus`，约 ¥5/次）测我们自己的竖屏基准成片，
拿一个独立眼睛的意见。原始报告：`external-vertical/wx-video-aa5e2adc….md`。

| 维度 | 外部分 | 我们本地自检 |
|---|---|---|
| Hook强度 | 7.5 | 前3秒语速 7.67、字幕 3 条、首镜角色=钩子 |
| 信息密度 | 8.5 | 全片 5.62 字/秒、22 个信息点 |
| 节奏控制 | 8.0 | 静止率 0.285、每卡死区 0/0/1.2/2.1/0/1.2/1.3/0.1 |
| 产品展示 | 4.0 | `external_pending`（本地算不了） |
| 情绪曲线 | 7.5 | `external_pending`（本地算不了） |
| 转化引导 | **2.0** | 末卡含 CTA = **否** |
| **总分** | **64.3/100** | — |

**这份读数的三个用处：**

1. **回答了一个我们判不了的问题。** 去问之前悬着的是「2.1s 静止算不算缺陷」——
   外部眼睛**没有点它**，反而把节奏评为 8/10（原话「保持了紧凑的节奏……有效避免了短平快内容的空洞感」）。
   结论：**不构成明显缺陷**。故暂不修改模板动效时长、也不改分镜；「每卡死区」从待修项
   **降级为观察项**，继续每片记录，等极差明显变大（例如出现 4s 以上 hold）再回头看。
2. **两处独立汇合，指明了下一步。** ① 转化引导：外部 2/10 与我们本地「末卡无 CTA」一致；
   ② 它给的节奏改进建议是「加转场音效做听觉切分」——而冻结文档已知缺口第 4 条正是
   「`visual`/`sfx` 只作文档、不驱动渲染（音效未做）」。**两处都指向比"改动效时长"更便宜、更对症的杠杆。**
3. **确立了外部锚点。** 64.3/100 是以后再跑外部检测时的对照起点。

**但它的细节仍然一个字都不能直接采信。** 同一份报告里：它把第 7 卡写成
「『人退到早上』（3分钟/1杯咖啡/24小时）」，真实是 **3段 / 1个 / 24h**——**编了两个值**；
第 1 卡的动词也读错（真实 `SLAMS`，它说"逐字显现"）。
用法边界不变：**当意见用，不当证据用。**

**一个流程问题**：该技能已**连续两次**崩在同一处——轮询里的 `TimeoutError` 没被兜住
（`poll_once` 直接调 `http_request`，绕过了重试包装），退出码 1，任务已创建、点数已扣。
两次都靠 `--task-id` 恢复拿回报告、不重复扣点。这是它的确定缺陷，不是偶发。
另外三次实测 `WX_VIDEO_POINTS_USED` **都未回传**，实际扣点需去 01Claw 账户看。
