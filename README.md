# code-news

`code-news` 是一个面向中文科普自媒体的 v3 内容运营仓库，当前主线聚焦三件事：找对标、做分析、生成可审阅的内容产物。

## 当前阶段

当前阶段优先覆盖以下链路：

1. 对标监控
2. 爆款分析
3. 仿写方案
4. 草稿生成
5. 插图与封面规划
6. 预检评分
7. 人工确认后的发布准备

当前阶段明确不默认视为已完成的能力：

1. 三平台正式自动发布
2. 发布后 72 小时数据追踪闭环
3. 小红书正式发文

说明：

1. 小红书当前只保留预发布策略位和风控相关工具，不进入正式发布链。
2. 仓库中保留了一部分历史发布脚本，但当前推荐主线以 `v3` 相关脚本和配置为准。

## 目录入口

- `config/`：内容域、工具映射、图片策略、接口占位配置
- `scripts/`：监控、生成、预检、状态写回、适配器脚本
- `tests/`：当前脚本层测试
- `docs/`：方案、runbook、执行计划、设计文档、模板
- `.tmp/`：运行产物和中间状态，不纳入版本库

## 当前重点入口

常用配置：

- `config/content_domains.json`
- `config/tool_registry.json`
- `config/image_strategy.json`

当前主线脚本：

- `scripts/run_benchmark_monitor.py`
- `scripts/run_content_signal_pipeline.py`
- `scripts/run_v3_content_ops.py`
- `scripts/check_generated_article_quality.py`
- `scripts/check_publish_readiness.py`

## 推荐工作流

建议按这个顺序推进：

1. 先更新对标池并跑监控。
2. 再做爆款分析和仿写方案。
3. 再生成草稿、插图计划和封面方案。
4. 跑预检与评分，确认没有重复发布、合规和低质风险。
5. 人工确认后，再进入正式发布动作。

## GitHub 协作约束

仓库协作默认遵循以下原则：

1. `main` 只保留稳定基线。
2. 新工作默认在功能分支上完成。
3. Issue 先定义目标、范围、验证方式。
4. PR 必须写清验证结果和风险。

## 现阶段判断标准

这个仓库当前追求的不是“发得越多越好”，而是三件事：

1. 选题方向正确
2. 内容与配图差异化足够
3. 发布前风险可见、可控、可复核
