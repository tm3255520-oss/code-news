## 6. 登记边界决策（2026-09-27）

**决策：15 条基础设施 cron 维持不入 `tool_registry.json`。**

理由：

1. registry 是「能力路由」，消费方 `scripts/tool_inventory.py` 与 `scripts/run_v3_content_ops.py` 都按 `interfaces` 取「能力」，不是按「任务」取。
2. 日志轮转、健康巡检、vault 同步、git 留痕、模型配置汇总等，不是可被 Agent 路由的能力；登记进去会稀释 registry 的语义。
3. 这类任务已有自己的追踪源：调度真相在 `.hermes/cron/jobs.json`，健康由 `cron_watchdog` + `hermes-doctor` 覆盖，日志由 Log Index / Log Watchdog 覆盖。
4. 纳入标准参照：registry 已收录 `proxy_health_check`、`browser_extension_inventory`、`tool_inventory` 等，说明标准是「能力」而非「定时任务」，基础设施任务不满足。

该决策已写入 `config/tool_registry.json` 顶层 `scope` 字段，随表生效，避免后续 Agent 重复误判。
