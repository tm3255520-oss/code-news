> 产线脚本：`C:\Users\Administrator\Documents\code-news\scripts\`（`lyric_*.py` / `compose_lyric_vertical.py` / `build_lyric_video.py`）
> 线资产：`D:\AI-VIDEO\lines\lyric-card\`（字体 / 粒子素材 / 出图提示词模板）
> 曲库：`D:\AI-VIDEO\music\lyric\`（怀旧风 BGM，与产线主库分开）

## 一、先记住这个认知（决定这条线便宜还是贵）

**动效 ≠ 图像在动。**

对标片看着"很动"，实测卡内 3 秒跨度里**只有 3-5% 的像素在变**，而且差异点
**均匀散布全画布（含上下模糊带）** —— 这说明动的不是画面，是**一层全屏粒子/光斑叠加层**。

→ 所以**不要开图生视频**（Wan2.2 / MiniMax H3 全免）。一层粒子就够，省掉整条最贵的链路。
→ 代价：卡内画面必须是静态图。要"动"就动叠加层，不动主体。

**另一个认知：源图用 3:4，不用 9:16。**
3:4 出图构图更容易稳、算力更省；合成时居中放 + 上下用同图模糊放大填充 → 9:16。
锐利区落在 y 12.5%-87.5%（可断言）。

## 二、一条命令出片


**输入只要两个文本文件**：`lyrics.txt`（一行一句）+ `scenes.txt`（一行一场景）。

## 三、五个环节，逐个可断言

| 环节 | 脚本 | 断言 |

| 粒子 | `lyric_particle.py` | `lyric_check.py motion` → 卡内 >8 灰阶差占比 2.8-6.5%，三段分布均匀 |

## 四、音频：三档可插拔（版权是唯一硬门槛）

## 五、🔴 七个踩过的坑（都真实发生过）

1. **xfade 的 duration 是重叠，会把成片压短 (n-1)×0.65s。**
   第一版成片 18.93s vs 音频 20.88s，卡片边界与音频整体错位 1.95s。
   → 每张卡底片与文字层长度必须是 `卡长 + PAD`，xfade 偏移取 `卡起点名义时间 - PAD/2`，
   成片末端 `-t total` 裁掉多余半窗。

2. **文字不该跟画面一起被入场模糊糊掉，但转场时又该一起糊。**
   对标片证据：0.4s 时画面还糊着、文字已经清楚（分层处理）；10.8s 转场时两边文字都糊。
   → 层序必须是：画面层 → 模糊包装 → **叠文字层** → 卡间 xfade；
   文字自己的出场模糊由 `lyric_textlayer.py` 的 EXIT_S 段负责。

3. **行锐度阈值法在低纹理区（天空）上失效。**
   实测清晰天空 p95 梯度 5、模糊带 4 —— 根本分不开。接缝检测也会被文字行的高频抢峰。
   → 成片用 `canvas` 校验：拿**已知源图**去匹配求垂直偏移，期望 240。

4. **入场不加 HOLD 段，转场中点只有 45% 清晰度，不像模糊溶解。**
   入场若从 t=0 就开始消模糊，转场中点它只走到 ~61%，和上一卡的半模糊叠起来仍有 56% 清晰。
   → 入场前 0.3s **保持全模糊**再开始消；出场把消模糊压缩到转场窗**前半段**完成。
   实测最低/最高锐度从 0.46 降到 0.14。

5. **负值参数必须写 `--rate=-18%`。**
   `--rate -18%` 会被 argparse 当成选项报错；跨脚本 subprocess 传参时同理。

6. **3:4 源图 + 上下模糊填充**，不是 9:16 原生出图。
   背景是 cover 缩放的模糊版（1.667× 中心裁切），前景是 1080×1440 居中。

7. **粒子定标要看数，不能凭眼。**
   第一版 120 粒子只有 0.56%（目标 3-6%），调到 720+132 才到 3.1%。
   亮度不够时，白点在亮天空上灰阶差 < 8，根本测不到。

## 七、文字层：🔴 v1.1 修正（这条最容易读错）

**对标片是「纯黑毛笔行书、无描边」，不是「白字 + 描边」。**
v1.0 从缩略图误读成白字描边，连带把字体和占宽都选错了；v1.1 逐卡裁原分辨率文字区后修正。

| 项 | 对标实测 | v1.0（错） | v1.1（对） |
|---|---|---|---|
| 颜色 | 纯黑 `#161412`，无描边 | 白字 + 黑描边 | `INK_COLOR`，`--style ink`（默认） |
| 字体 | 行书（粗细对比强、笔锋明显） | 马善政毛笔楷书（粗圆） | **华文行楷 `STXINGKA.TTF` + 同色加粗 2px** |
| 单行占宽 | **66.4%**（717px / 9 字） | 89.1%（几乎贴边） | **67.8%**（`TARGET_W_RATIO=0.67`） |
| 单字 advance | 71.7px | 96.2px | ≈80px |
| 纵向密集带 | 20–25% | 无密集带 | 20–25% ✅ |

- 字体候选在 `D://AI-VIDEO//lines//lyric-card//fonts//`（4 款 OFL 免费商用）；**默认用系统 `STXINGKA.TTF`**
- `--style white` 保留旧的"白字+描边"风格（可选，非对标风格）
- `fit_size()` 的口径是 **`目标宽 ÷ 每行字数` 反推字号**（≤10 字 1 行 / ≤20 字 2 行）。
  这条改过三次才对：① "能塞下就行" → 89%；② `getlength/行数 ≤ 目标` → **换行把条件满足了**，
  选到上限仍是 2 行 86%；③ "每行都要 ≤ 目标" → 又变成能多小就多小，掉到 62%。
  **另：`fit_size` 与 `render_block` 的折行宽必须同一个口径**，否则一个按 67% 算"两行"、
  另一个按 95% 又拼回一行（实测占宽 86.7%）。

## 七·补、比对工具与量测口径（`lyric_benchmark.py`）

`python scripts/lyric_benchmark.py --ref <对标> --ours <本线> --ref-windows "a:b,c:d" --ours-windows "a:b,c:d" --canvas-at 2.5 --out bench.json`

同工具同指标跑两片。**四个量测口径坑（都踩过，脚本里已修）**：

1. **`np.abs(uint8 − uint8)` 会 mod 256 回绕** —— 把卡内静止 3.9% 报成 35%。必须先 `.astype(np.float32)`。
2. **行锐度阈值法在低纹理天空上失效**（清晰 p95=5 vs 模糊 p95=4）；接缝检测会被文字行抢峰。
   → 改用**归一化梯度** `hf/(lf+2)`（纹理无关）。
3. **粒子污染**：本线粒子抬高全画布高频，半分辨率下"模糊平台"0.088 vs 对标 0.044 → 阈值被抬高，本线边界测不出。
   → 降到 **1/4 分辨率 + 5×5 中值滤波**。修正后两片都是 y 11.67%–88.33%，**完全一致**。
4. **采样点会撞转场**：`dur×0.25` 对对标片正好落在转场帧里 → 必须**显式指定卡 1 中段**（`--canvas-at`）。

> ⚠️ **卡内静止性必须两片用同样的窗口长度**：窗口越长粒子扫过面积越大，
> 同一条片 2.9s 窗给 3.0%、4.0s 窗给 53%——差 17 倍是口径差不是质量差。

## 八、边界（别越界）

- 卡内画面是静态图，**没有**真实镜头运动。要真运动就得上图生视频，本线不做。
- 生成式 AI 图的**商用授权**要看具体模型条款，出片前自行确认。
- 母带规范是 **-14 LUFS / TP ≤ -1.0 dBTP**；对标片是 -9.3 LUFS / +0.89 dBTP（**削顶，不学**）。
- 竖屏 1080×1920 / 30fps / h264，输出 `-crf 18`。
- **配色取向与对标有差**：出图 prompt 里的「暖色调，黄昏金光」会让主色整体偏暖米黄；
  对标是**冷蓝天 + 暖金地**并存。要更贴就把 `build_lyric_video.py` 的 `STYLE` 改成双色描述。
