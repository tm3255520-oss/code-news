# 我方物理质量基线

> 建立于 2026-09-17。**用途：给"这条对标片是否值得学"提供一个我方参照**。
> 用户 2026-09-17 提醒：「播放量高 ≠ 物理质量高。有些视频数据好是文案/话题/标题的功劳，
> 不能因为播放量高就给它出改进建议。」——本目录就是那条判断的锚。

## 怎么产生的

用**同一个分析工具**测我们自己的验收基准成片（与对标片同一套判据，避免"拿不同尺子量"）：

```bash
python scripts/analyze_video_production.py video-line/acceptance/landscape/final.mp4 --out <目录>
python scripts/analyze_video_production.py video-line/acceptance/vertical/final.mp4  --out <目录>
```

原始 JSON 原样存在本目录（`ours-landscape.json` / `ours-vertical.json`），未做任何编辑。

## 基线值（2026-09-17）

| 指标 | 我方横屏 1440×1080 | 我方竖屏 1080×1920 | 可比性 |
|---|---|---|---|
| 母带整体响度 | **−21.54 LUFS** | −21.54 LUFS | ✅ 可比（平台不改创作者混音） |
| 母带真峰值 | **−4.1 dBTP** | −4.1 dBTP | ✅ 可比 |
| 语速 | 5.38 字/秒 | 5.38 字/秒 | ✅ 可比 |
| 字号档 | 81.8 / 14.1 px | 106.1 / 56.5 / 14.1 px | ✅ 可比（设计层） |
| 场景数 / 中位镜头 | [1,13] / 2.76s | [4,9] / 2.96s | ✅ 可比（相对值） |
| 居中率 | 0.0（标题左对齐） | 0.0 | ✅ 可比，但**是风格不是质量** |
| 强调色 | #B2ED5B | #7BA24D | ✅ 可比 |
| 码率 / bpp | 1474 kbps / 0.0316 | 1778 kbps / 0.0286 | ❌ **不可比** |
| 编码 | h264 | h264 | ❌ 不可比 |

## 为什么码率/编码不可比（重要）

我们的 JSON 来自**本地导出件**；对标片的视频文件是**平台转码后的交付件**
（抖音 242 kbps、视频号 157 kbps、B 站 av1 630 kbps）。两边不同源，
拿这个比会得出"我们画质高 6 倍"的错误结论。
**要与对标比画质，只能拿原始导出件比**（见 SKILL.md 已知边界）。

## 我们自己基线暴露的问题（这份基线的价值所在）

1. **母带太闷**：−21.54 LUFS 比平台标准（约 −14）低 7.5 dB，真峰值只用到 −4.1（留了 3 dB 余量没用上）。
   → 平台播放时会被"归一化"提升，动态细节被压缩，听感发闷。这正是产线该补 loudnorm 的直接证据。
2. **字号档偏少**：横屏只有 2 档（81.8 / 14.1），对标片是 3 档（如 103/71/19）。
   → 层级少的直接后果是"标题与正文之外没有中间层"，批注/副标题没地方放。

## 判定规则（写报告时必须遵守）

对每个环节：

1. **先比可比项**（母带 / 语速 / 字号档 / 节奏 / 版式结构 / 强调色）；
2. **对标片 ≥ 我方** → 可提"照它改"；
3. **对标片 < 我方** → 写「不改」，理由写「低于我方基线」；
   **并注明：它的高播放量应归因于文案 / 选题 / 标题**（那属 `viral-video-breakdown` 的职责，不属本工具）；
4. **不可比项**（码率 / 编码）→ 写明「不可比」并说明原因，**不得据此下结论**；
5. 风格项（居中率、字幕样式、切换方式）→ 标「风格差异，不是质量差异」，改与不改由产线定位决定。

## 什么时候更新

产线模板有实质改动后（如画幅、字号体系、混音链）重新跑一次本目录的两条基线，
并在提交信息里写「我方基线已更新，原因是 X」。
