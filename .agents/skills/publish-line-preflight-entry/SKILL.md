# 给一条发布线建「通道矩阵 + 只读体检入口」

> （§13.4 判据必须有区分度 / §13.7 蚁小二图文线体检入口 / §13.8 渠道既有图文线体检入口）
> 与 `系统中枢/协同/发布层模块契约卡.md`（§三 通道清单 / §四·补 / §四·补2 / §五 退出码 / §十一 同名陷阱）。
> **本 skill 是它们的可执行版。**

## 〇、什么时候该建这个件

**信号**：某条线"发布前要查哪几样"只存在于人脑/聊天记录里 → 每次发布现场重新判断 → **漏查就白跑一轮**。

**已有实例（本机，可直接照抄结构）**：

| 线 | 平台 | 体检件 |
|---|---|---|
| 视频线 | 抖音 / 快手 / 小红书 / 视频号 | `~/.hermes/scripts/publish_preflight.py` |
| 蚁小二图文线 | 小红书 / 视频号 / 抖音 / 快手 | `~/.hermes/scripts/publish_preflight_image.py` |
| 渠道既有图文线 | 微信 / 知乎 / 头条 | `~/.hermes/scripts/publish_preflight_article.py` |

**建之前先问**：这条线的平台集合、通道机制（API / 浏览器 / CLI / 第三方客户端）**是不是和已有线重合**？
重合但字段/机制不同 → **照建独立件**，别硬塞进已有的表（理由见 §五·1）。

## 一、硬纪律 1：判定原语一律 import 复用，绝不另写一套

否则三条线会各自漂移，同一种状态在 A 件叫 `OK`、在 B 件叫 `READY`。

```python
from publish_preflight import (          # 视频线是"判定原语库"
    OK, REACHABLE, EXPIRED, NEEDS_SETUP, UNAVAILABLE, UNKNOWN,
    Probe, _ICON, _exit_code, _pad, _run, _verdict, _w,
)
```

- 状态机固定六个：`OK / REACHABLE / EXPIRED / NEEDS_SETUP / UNAVAILABLE / UNKNOWN`。
- 退出码固定 **0 / 7 / 2 / 1**，优先级 **7 > 2 > 1 > 0**（`_exit_code` 已实现，别重写）。
- `REACHABLE` = **通道可达但"登录态 / 写能力"未实测** → 结论给 🟡，**不给 ✅**。
- 两种口径并存：默认**体检口径**（只看主通道）；`--fallback-ok` = **门禁口径**（任一条腿有路即算过）。

## 二、硬纪律 2：有数值的只留一处

契约表（标题上限 / 正文长度 / 图片张数 / 可见枚举 / 有无草稿箱）**必须只有一份**，否则必然写错值。

优先级：**① import 现成常量 → ② import 现成表 → ③ 集中在件内并逐条注明来源**。

```python
# ① 能 import 就 import（本机实例）
from publish_via_yxer_image import IMAGE_TEXT_SPEC          # 图文线：契约表
from toutiao_publisher import ToutiaoPublisher              # 头条：VALID_DECLARATIONS / VALID_COVER_MODES
from publish_via_matrixmedia import TITLE_MAX               # 矩媒：分平台标题上限
from check_publish_readiness import PLATFORMS, latest_publish_record   # 本地证据（profile / 最近记录）
```

**注意**：`check_publish_readiness.py` 是**本地就绪**检查（profile 目录在不在 + 最近发布记录），
**不是**通道级体检 —— 只能当 detail 佐证，**不能**当判定；也**不要改它**（被运行手册引用）。

⚠️ **它的落点不在 `~/.hermes/scripts/`，而在 `code-news/scripts/`**（2026-10-12 实测）。
体检件能 import 它，靠的是件内显式跨目录：
```python
CODE_NEWS_SCRIPTS = Path(r"C:\Users\Administrator\Documents\code-news\scripts")
sys.path.insert(0, str(HERMES_SCRIPTS)); sys.path.insert(0, str(CODE_NEWS_SCRIPTS))
```
→ 将来挪动 `code-news/scripts/` 会**静默打断**这条 import（探针降级成"取不到"而不是报错）。

## 三、硬纪律 3：探针必须能区分「配置在」与「真能用」

**恒真的值不是判据**（§13.4）。分两档：

- **默认（浅探针）**：只读本地 —— `shutil.which()` 探 CLI、读配置文件、读 profile/记录目录。
  结论一律 `REACHABLE`，detail 里明写 **"未实测"**，action 写"需要时加 `--deep`"。
- **`--deep`（实测）**：真去问一次。**必须把副作用写进 docstring 和输出里**，别偷偷做。

本机 `--deep` 的三类副作用（**已知，必须如实标注**）：

| 探针 | 副作用 | 说明 |
|---|---|---|
| 微信取 `access_token` | **刷新上一个 token** | 若产线每次都现取则无害；但**不是零副作用** |
| `bsk status` | 无 | **只读状态**，不 `session start`（这是红线） |
| `toutiao-ops auth check` | **可能起一次无头浏览器** | 不发布、不写任何东西，但确实起进程 |

⚠️ **绝不**在体检件里做 `validate` / `--dry-run` 冒烟 —— 那一步**会上传素材**（"不投递" ≠ "零副作用"）。

### 三·补、**单字段判据不够** —— 该用「复合判据」（2026-10-10 硬反例）

**`status=1` 不是充分条件。** 2026-10-10 01:01 视频号发布**实际失败**
（`yxer query details <task_set_id>` → `errorMessage = 获取用户信息失败登录失效`，`stages=upload`），
但 `yxer accounts list 视频号 --json` 返回的是：

```
"status": 1, "isLock": false, "isFreeze": false, "isOperate": true, "fansTotal": 9
```

**一个"不正常"的字段都没有** → 当天 08:58 与 14:16 两次体检**仍报 `✅ 可发`**。
根因：`status` 是**蚁小二侧的账号绑定标志**，**与平台侧登录态无关**。

**正确姿势**：判据必须是**复合**的 ——

| 通道 | ❌ 不够 | ✅ 复合判据 |
|---|---|---|
| 蚁小二 yxer | `accounts list` 里有该平台 / `status=1` | `status=1` **且** 该平台**最近一条**记录非 `allfailed` |
| 矩媒 | `/platforms` 的 `automated` / `hasConfig` | + **账号树**条目 + **投递记录**最近实投结果 |
| x-mcp | `check_login_status` 报已登录 / `success=true` | **返回体有实质内容**（`nickname`/`user_id` 非空） |

**并且：要判"真的发出去了"，必须回读平台侧任务状态** —— 脚本打印 `ok:true` **只代表"CLI 收下了这次提交"**：

| 平台 | 回读方式 |
|---|---|
| yxer 全平台 | `yxer query details <task_set_id> --json` → 看 `tasks[].stageStatus` / `errorMessage` |
| 头条 | `draft_list` API 反向验证（该仓库已实现） |

⚠️ **发现判据不完整时**：若该件是**已验证资产**（有全绿自测），**默认只报告不擅改**（`repair-gate`）。

#### 三·补·A 落地时必踩的**三个坑**（2026-10-10 实测，已实现）

`probe_yxer()` 已升级为复合判据（`status=1` + 该平台最近一条记录）。**实现时必须注意**：

1. **`yxer query records --platform <平台>` 不生效** ——
   `--platform 视频号 --limit 10` 返回 **10 条**，`platforms` 分布 `{('视频号',):3, ('小红书',):1, ('抖音',):6}`。
2. **`--status` 也不生效** —— `--status allfailed --limit 10` 仍混入 **8 条** `allsuccessful`。
   → **过滤必须由客户端自己按 `record["platforms"]`（数组）做**，再取 `createdAt` 最大者。
3. **`errorMessage` 不在 `query records` 里**，只在 `query details <taskSetId>` 里
   → 为控 **N+1**，**只在**最近一条是 `allfailed` 时才多调一次 `details`。

**三分支语义（别简化）**：

| 最近一条记录 | 判定 | 为什么 |
|---|---|---|
| `allfailed` | **降级 `EXPIRED`** + detail 带时间/标题/`errorMessage`，action = 去蚁小二重新授权 | 实投失败是硬证据 |
| `allsuccessful` | 保持 `OK`，detail 附「最近实投 <时间> 成功」 | 有正向物证 |
| 取不到 / 查询失败 | **不降级**，detail 注明「最近记录未取到」 | **查不到 ≠ 账号坏**（别把网络抖动报成账号失效） |

**收益会自动传导**：因另一条线是 `import` 复用 `probe_yxer`，改一处，两条线同时不再假绿。

### 三·补2、**「环境不可用」≠「账号失效」**（2026-10-10 第二个反例，很值钱）

**用户说「头条已经登录」，但体检报"未登录" —— 体检错了。** 真因：

```
$ node <toutiao-ops>/index.js auth check --account default
{"error": "browserType.launchPersistentContext: Executable doesn't exist at
 ...\ms-playwright\chromium-1234\chrome-win64\chrome.exe ... npx playwright install"}
$ ls <ms-playwright>/
chromium-1169  chromium-1208  chromium-1223      ← 没有 1234
```

`auth check` **起不了浏览器** → 返回体**只有 `error`、没有 `logged_in` 字段** →
上游封装 `_check_login()` 把异常**吞掉后 `return False`** → 被当成"未登录" →
报 `⛔ 失效`、处置写**"去扫码"**（**方向全错**；正确处置是**装浏览器**）。

**根因模式（通用）**：**凡是"异常被吞成 `False`"的封装，都会把「环境坏」误报成「账号坏」。**

**修法：自己解析返回体并归类**，不要复用会吞异常的布尔封装：

| 返回体 | 状态 | 处置 |
|---|---|---|
| 非 JSON | `UNKNOWN` | 人工跑一次看完整输出 |
| **有 `error` / 无关键字段** | **`UNAVAILABLE`**（退出码 **2** 可重试） | 修环境（如装 Playwright 浏览器） |
| 关键字段 == 成功值 | `OK` | — |
| 关键字段 == 失败值（**明确返回了 false**） | `EXPIRED`（退出码 **7** 需人工） | 重新登录 |

> 🔴 **纪律**：报「账号失效」之前，先问一句 **"这是账号的问题，还是环境的问题？"** ——
> 两者处置完全不同（重新登录 vs 装依赖），**误报会把人的时间指到错的方向**。
> 若吞异常的封装在**别人的文件**里 → **只报告不改**（`repair-gate`），改自己那一层。

## 四、硬纪律 4：无备用腿要用**显式哨兵**，结论不粉饰

```python
NO_FALLBACK = "-"                     # 显式哨兵，不静默当成"没探"
ARTICLE_CHANNELS = {"微信": ("gzh-api", NO_FALLBACK), ...}
def fallback_key_or_none(p):          # 归一成 None 供聚合判断
    fk = ARTICLE_CHANNELS[p][1]
    return None if fk == NO_FALLBACK else fk
```

- 主通道失效 + 无备用腿 → **`❌ 不能发`**（不给"勉强可用"的软话）。
- **判"备用腿"要先问"它是不是独立的一条腿"**。本机踩过的假备用：
  - 微信 `wenyan-mcp` 与主通道**共用同一套凭证**（`config.yaml` 同一段）→ 40164 / 40001 时**同挂**；
  - 知乎 `auto_publish_zhihu.py` 与主通道是**同一套 bsk 机制**（仅修过 bug）；
  - 矩媒 `publish_via_matrixmedia.py` 是**视频**形态（`--video`）→ **不是图文腿**；
  - `tie_tu_publisher.py` 是**贴图专项**（`article_type=newspic`）→ **不是通用图文备用**。
  → 真独立腿的判据：**机制与登录态存储都不同源**（如头条 `bsk-native` 走 bsk+Profile2，
  主通道 `toutiao-ops` 走自有 `browser-data` 目录）。

## 五、硬纪律 5：自测不碰外部状态，且"同源"要**实测比对**而不是自称

- `--selftest` 必须**零外部依赖**：只验通道矩阵完整性、契约行、命令模板、纯函数。
- 需要外部状态的证据源，用**临时目录 / 临时文件**做（本机实例：矩媒证据源用 `TemporaryDirectory()`）。
- **"同源"要证明**：把两个实现喂**同一份输入**，断言输出一致。本机实例：

```python
# 微信凭证正则：让本件与 gzh_publish_draft 解析同一份临时 config，断言结果相同
HERMES_CONFIG = fake_config
mine = read_wechat_creds()
_g.CONFIG_PATH = fake_config; _g.load_credentials()
assert mine == (_g.APPID, _g.SECRET)     # ← 这才叫"同源"
```

- 断言要用**源码里真实存在的文本**（别手打）。踩过：手写 `[0, 1, 2]`（带空格）而源码是 `[0,1,2]` → 假失败。

## 六、硬纪律 6：落盘原子化 + 行尾按字节保留

- **行尾真值只看 bytes**：`read_bytes().count(b"\r\n")` vs `count(b"\n")`。
  ⚠️ shell `grep -c $'\r'` 会**把纯 LF 文件误报成 CRLF**（本机踩过）。
  本机惯例：工作流/契约卡/memory/技能日志 = **LF**；台账/交接/jsonl/运行小结 = **CRLF**。
- **原子写**：先把所有 `old` 串断言"恰好命中 1 次"，**全部通过后才写任何文件**；
  再做"归一成 `\n` 替换 → 按原 EOL 还原 → 写 bytes"。
- 登记要**多处同步**（本机清单）：工作流 §13.x → 契约卡 §三/§四·补/§七/§八/§十/§十一 →
  台账 → 交接 → 会话索引 jsonl → 运行小结 → memory → 技能变更日志。

## 七、发现真故障怎么办

**默认只报告，不动手**（`repair-gate`）。本机第 6 轮 `--deep` 一跑就抓出两条真故障：

- 微信 `40164`（出口 IP 不在白名单）→ 人工去 `mp.weixin.qq.com → 设置与开发 → 基本配置 → IP白名单`；
  **Clash TUN 下要让 `api.weixin.qq.com` 走 DIRECT**，否则出口 IP 会漂移。
- 头条 `logged_in=false` → 人工 `toutiao-ops auth login` 扫码。

**两条都不是代码问题** → 写进"待处置（人工动作）"清单，**不擅自改代码**。

## 八、多线并存时：**补一个只调度的「总入口」**（2026-10-10 定）

当一条条线建起来后，会出现**三条命令、三个名字**的局面 —— 这是**漏跑**的温床：
只跑了其中一条就以为"全线体检过了"。**这正是"同名陷阱"的同类失败模式。**

**但"统一入口" ≠ "合并实现"** —— 两件事要分开：

| | 做法 | 风险 |
|---|---|---|
| ✅ **统一入口** | 新增一个**只调度**的总入口：`subprocess` 调各子件（各带 `--json`）+ 只做汇总与退出码合并 | **零风险**（不动任何已验证资产） |
| ❌ **合并实现** | 把多条线塞进一个文件（`--line` 分支） | 要动已验证资产 + 引入分支耦合 |

**总入口的硬要求**：

1. **零判定逻辑** —— 只 `subprocess` + 汇总，**不 import** 子件的判定函数；
2. **退出码合并**沿用同一套语义（`7 > 2 > 1 > 0`）；
3. **子件跑不起来 → 记 `UNKNOWN`（退出码 1）**，不静默跳过；
4. **`--deep` / `--fallback-ok` 原样透传**，并在 `--deep` 时**显式警告副作用**；
5. **自测要"证明没 import 判定模块"** —— 用 `sys.modules` 断言 + 源码片段断言：
   ```python
   chk("publish_preflight" not in sys.modules, "未 import 判定模块")
   needles = ["_" + "verdict(", "from publish_preflight " + "import"]   # 拼接构造，避免自指假失败
   ```
   ⚠️ 踩过：把断言串**直接写成字面量**会导致"断言串自身出现在源码里"→ **自指假失败**。

本机实例：`~/.hermes/scripts/publish_preflight_all.py`（三条线，自测 25 项全绿）。

6. **`repair-gate` 实操（改已验证资产时）** —— 若判据缺陷在**已验证资产**里（有全绿自测），
   默认只报告；用户授权后按这条路径走：
   **① 报告（含现象/位置/证据/根因判断/影响面/建议）→ ② 用户确认 → ③ 由专用推理模型会话
   先独立复验问题真实存在 → ④ 在该会话修理 → ⑤ 带真实运行证据。**
   - **动手前先备份**（`Documents/agent-work/<task>-rN-backup-<ts>/`）；
   - 明确**边界**：不许改状态名 / 退出码语义 / 判定原语；不许碰**别人主责**的文件（只报告）；
   - 改完**自己独立复核**（别只信子会话的汇报）：`diff -q` 确认只有授权文件变了、
     跑全部自测数项数、跑**反例**看是否真的不再误报、扫违禁调用、验行尾。
   - ⚠️ **项数会漂**：文档里的「N 项全绿」要**实测再写**。本机踩过：把 `--selftest` 的项数
     凭印象写成 47，实测基线是 **46** —— 由专用会话对照备份文件才纠出来。

## 九、收口检查清单

1. `--selftest` 全绿（项数写进契约卡与交接）；
2. 默认只读实跑一次，`--deep` 实跑一次（**把副作用如实标注**）；
3. **零投递复核**：确认没有新增投递记录（本机 = `yxer query records` 的 `imageText` 计数 + 各渠道
   本地 `*-publish-records.json` 的 mtime）；
4. 登记全部落盘，`check_doc_references.py` 无**新增**断链；
5. **发现"单字段判据不够"或"多线漏跑"这类通用问题 → 回头更新本 skill（§三·补 / §三·补2 / §八）**。

## 十、换通道（改路由）时的三条纪律（2026-10-10 补）

"这条线换走另一条通道"是**改路由**，不是小改。踩过的坑：

### 十·1 **先实测现状 —— "以为"不等于"知道"**

用户说"让 X 走直连"，别直接去改代理配置 —— **先测一下它现在走的是什么**。
本机实例：微信 API 报 `40164 invalid ip`，直觉是"被代理路由到节点了"，
于是准备去加 Clash 规则。**实测**（分别用「走系统代理」与「强制直连」调同一个接口，对比对端回报的 IP）：

```
走系统代理：invalid ip 120.229.171.123 ...
强制直连：  invalid ip 120.229.171.123 ...     ← 同一个 IP
```

→ **它本来就是直连**，真正要做的只是把该 IP 加进平台白名单。
**若不做这一步，就会去改一个根本不需要改的东西**（还会以为改好了）。

> **判据**：凡"改配置就能修"的判断，**先测出当前的真实状态**，再决定要不要改。

### 十·2 **改路由 ≠ 改语义** —— 默认保持原语义

用户要换的是**走哪条通道**，通常**不是**"改变发布语义"。
本机实例：视频号原本走蚁小二 = **草稿箱**（人工确认后发布）；迁到矩媒时**仍取草稿箱**，
**没有**因为矩媒默认 `--mode auto` 落到 `scheduled`（= 定时自动公开）。

> 若目标通道**做不到**原语义（如"没有草稿箱"），有两个选择：
> ① **fail-safe**：仍然要求草稿语义 → 不支持就**报错退出**（不会静默降级成自动公开）；
> ② 改语义 → **必须显式向用户确认**（自动公开通常撞"绝不自动公开"红线）。
> **默认选 ①。**

### 十·3 改 cron 路径前，先问「**当前是不是本来就坏的**」

若这条通道**当前本来就发不出去**，那么改动的风险是"零"（不可能更坏），属**纯增量尝试**；
反之若当前是好的，改动就可能**把它改坏** → 必须更保守（先备份 + 更充分的验证）。
本机实例：视频号当时因蚁小二登录失效**本来就发不出去** → 迁矩媒不可能更坏。

**配套**：改完要验三样 —— ① 命令能跑（用 `--dry-run` / `--check-only` 这类**不投递**的口子）；
② 体检件显示的路由已变；③ **全部自测仍全绿**。

## 十一、用户说「**测试整条发布生产线**」时的执行姿势（2026-10-12 实战定）

**信号**：用户说「对整个发布生产线做测试，给出测试结果，然后才考虑恢复 M1 / 上线 / 继续推进」。
**别另写测试脚本**（§十二 禁重复开发）—— **就用已建好的体检件**，这是它们存在的意义。

### 11·1 五步执行

1. **先证明起点是好的**：四条 `--selftest` 全绿
   （本机实测项数：总入口 **25** / 视频线 **56** / 蚁小二图文线 **44** / 渠道图文线 **53**）。
2. **跑两遍，两个口径** —— 浅探针（默认）+ `--deep`，**报告里必须分开列**。
3. **`--deep` 的副作用如实标注**（刷新微信 token / 可能起无头浏览器），**强调"均不投递"**。
4. **零投递复核**：确认没有新增投递记录（各渠道本地 `*-publish-records.json` 的 mtime 未变）。
5. **产出必须含「恢复判据」清单**（见 11·3），不是只给一张状态表。

### 11·2 🔴 铁律：浅探针的 `🟡` **不等于** `✅`

浅探针（只读本地）对「配置在不在」下结论，一律给 `REACHABLE` → 显示 `🟡 主通道可达（需实发验证）`。
**只有 `--deep` 才回答「能不能真发」。**

本机实例（2026-10-12，同一时刻两口径对比）：

| 平台 | 浅探针 | `--deep` | 结论差异 |
|---|---|---|---|
| 知乎 | 🟡 | **✅ OK** | 实探通过 |
| 头条 | 🟡 | **✅ OK** | 双腿（CLI + bsk-native）都 OK |
| 微信 | 🟡 | **❌ 不能发** | **实测挖出真故障**（`40164` 出口 IP 不在白名单） |

→ **报告里若把 🟡 汇总成 ✅，就是把"没测"报成了"通过"** —— 这是比误报故障更危险的粉饰。

### 11·3 「恢复某条线」的判据清单（**6 条，第 5 条最常被漏**）

| # | 判据 | 说明 |
|---|---|---|
| 1 | **环境就绪** | 该线依赖的环境前置已通过（如发布线的 patchright M0） |
| 2 | **浏览器/通道桥健康** | `bsk doctor` 七项 ok、`session start` 不报 `No SW` |
| 3 | **体检件自测全绿** | 四条 `--selftest` 全过 |
| 4 | **通道体检无 `❌`** | ⚠️ 但要判断**是否阻断**：若目标里程碑**只做草稿/干跑**且走独立通道，别线的 ❌ **不阻断** |
| 5 | 🔴 **互斥条件** | **与本线同改一个目录、且共享浏览器环境的另一条线，是否已收口？**（本机：发布线与评论互动线都改 `~/.hermes/scripts/` → **不得同时开工**）。**这条最容易漏，漏了就是白跑一轮** |
| 6 | **人在场** | 需要扫码登录 / 验证码的步骤，必须用户在场 —— 写进结论里提醒 |

### 11·4 实测挖出的故障怎么处置

**默认只报告，不动手**（`repair-gate`）。本机实测的典型两类：

| 故障 | 类型 | 人工动作 |
|---|---|---|
| 微信 `40164 invalid ip` | **外部配置**（IP 白名单） | `mp.weixin.qq.com → 设置与开发 → 基本配置 → IP白名单` 加当前出口 IP；⚠️ Clash TUN 需让 `api.weixin.qq.com` 走 **DIRECT**（否则 IP 漂移、今天加明天失效） |
| 蚁小二某平台 `EXPIRED` | **账号态**（登录失效） | 客户端重新授权该平台 |

> 判「账号失效」前先按 §三·补2 问一句：**这是账号的问题，还是环境的问题？** —— 两者处置完全不同。
