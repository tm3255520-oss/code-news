## 一、铁律：先核实，再整改

**派单里写的现状常常与实况有出入**（实测两例：A3 写「74 条跑中」实际是「83 条且已停 + 44 条真失败」；B2 写「◐ 需实测」实际是「已实测失败」）。
→ **逐条核实后才动手**，并在交接块/变更记录里如实写「与派单的出入」，不粉饰。

核实手段：
- 台账/交接：直接读文件末块；
- 转录/采集类：读 `~/.hermes/scripts/.progress_*.json`（done/failed/skipped 计数 + mtime）+ **按作品 ID 在 vault 里核对落盘**（别只信进度文件）；
- 发布线：读 `~/.hermes/cron/output/*.txt`（cron 实投日志）+ 跑 `publish_preflight*.py`。

## 二、巡检判据（改之前先知道脚本怎么判）

| 类别 | 判据 | 消除办法 |
|---|---|---|
| **停滞** | `状态 ∈ {进行中, 待审}` 且 `updated_at` 距今天数 > `--stale-days`(默认 7) | 置 `暂停`（写阻塞原因）或 `已完成`；或推进后更新「最后更新」 |
| **格式** | ① 台账行缺负责人 / 状态非法 / 时间戳不可解析；② 交接块缺字段 | 台账行补全；交接块补字段行 |
| **断链** | 活跃任务无交接文件；交接文件在台账无对应行；产出路径不存在 | 补文件 / 补台账行 / 更正路径（⚠️ 产出路径列只放纯路径，说明写进变更记录） |
| **重复** | 同平台 + 标题有共同词元的两个活跃任务 | 合并或明确区分 |

### 🔴 二·补：「重复」必须先分真伪（2026-10-13 新增，动手前必读）

用户说的「重复」与巡检报的「重复」常不是一回事。先分类，再决定动不动手 —— **大部分「重复」是不该改的**：

| 形态 | 判定 | 处置 |
|---|---|---|
| **登记重复**（同任务多行 / 多块） | 协同件是**只追加**设计，同一任务多次收工必然留多行多块 | **正常形态，不改**（合并会违反只追加纪律、丢可追溯性） |
| **同号指向不同任务**（备份区 `WK-<日期>-<序号>` 撞号） | **真问题** | 另编空号（见 §七·撞号条） |
| **悬置未闭合**（老块「未决问题」实际已被后续任务解决） | **真问题** | 回到该块所属文件**追加订正块** |
| **代码/配置双写**（两个会话同时改同一文件） | 需实测 | 查定义计数与 mtime（如 `def f` 出现次数、单点写入） |

- 🔴 **假阳性警告：字节数 ≠ 字符数**。`len(open(p, encoding='utf-8').read())` 得到的是**字符数**（中文 1 字 = 3 字节）；拿它去跟 `os.path.getsize()` 或他处记的字节数比，会凭空算出「少了几十 KB」的**假截断**（本次实测：台账 165768 是字符数、239835 才是字节数，一度误判丢失 70KB）。
- **判有无丢失的正确办法**：拿历史备份快照做**集合差** —— 比对两份台账的 WK 号集合，看「备份独有的 WK 号」是否为 0（为 0 即纯追加无损）。别靠体积比对。

**交接块字段（`BLOCK_FIELDS`，7 个）**：本轮做了什么 / 动了哪些文件 / 证据 / 未决问题 / 下一步 / 建议接手方 + 该调的 skill / 状态。

`FIELD_RE` 允许三种写法：`- 字段：值`、`**字段**：值`、`字段（备注）：值`。
→ **叙述式加粗小标题（如 `**确认**：`、`**遗留**：`）不算字段** —— 这是「缺字段」告警的常见根因。

**关键推论**：总判据 `findings=0` 通常**只需完成 §A 台账卫生**（findings 只来自台账行 + 交接块），§B 发布线问题不在巡检口径内。

## 三、整改动作

### §A 台账卫生（零风险，可直接做）
1. **停滞行**：按实况置 `暂停`（阻塞原因写进交接块「状态」字段）或 `已完成`；把「最后更新」改为当前时间（`YYYY-MM-DD HH:MM`）。
   - 判据：置 `暂停`/`已完成` 后该行不再进 `ACTIVE_STATUSES` → 停滞告警消失。
2. **缺字段块**：在块末尾（最后一个非空行之后）**追加**字段行，内容从该块原有叙述里提炼。**不改动原有叙述行**（只追加、不覆盖）。
3. 台账末尾**追加一行变更记录**：`| YYYY-MM-DD HH:MM | <agent> | 改 <任务ID列表> | <说明+依据> |`。

### §B 产线问题（多需人工 / 走三段）
- 需人工的（客户端重新授权、后台登录、IP 白名单）：**只报告 + 标注待人工**，脚本代不了。
- 属代码/配置改造的：**出计划卡，走三段（计划卡→build→verify，验证由非实施方）**，不在本 skill 内实施。
- 状态登记更新（如契约卡通道状态 ◐→⛔）：可做，但**必须附一条可复核的实测证据**（cron 日志行号 / 命令+退出码）。

### §C 仅登记
暂停行、需用户本人动作的行 —— 不动，只在报告里列出「一句话即可重启」。

## 四、行尾纪律（🔴 必守）

`协同/` 下文件**不统一，逐文件按字节判**：
- **纯 CRLF**：`任务台账.md`（含 `.bak-*`）、`交接/WK-*.md`（例外：`WK-20261004-09.md` 是 LF）、`会话索引/workbuddy.jsonl` / `dsh.jsonl` / `hermes.jsonl`
- **纯 LF**：`_使用说明.md`、`交接/_模板.md`、四张模块契约卡
- **MIXED（危险）**：`会话索引/codex.jsonl`、`claude-code.jsonl` —— 用 `Edit` 会被静默归一为 LF

**正确改法（推荐全程用 Python 脚本，别用 Edit 改 MIXED 文件）**：
```python
CRLF = bytes([13, 10])
raw = pathlib.Path(p).read_bytes()
assert raw.count(CRLF) == raw.count(b'\n')          # 自证纯 CRLF
lines = raw.split(CRLF)                              # 按 CRLF 分行
# ... 替换 / 插入 ...
out = CRLF.join(lines)
assert out.count(CRLF) == out.count(b'\n')           # 复证行尾未破
pathlib.Path(p).write_bytes(out)
# 再复读磁盘、用 in/count 校验关键串真的在位
```
中文一律用 `'…'.encode('utf-8')` 运行时编码，**不在源码里写 `b"中文"` 字面量**；正文别塞进 `.py` 三引号（会透传脚本自身行尾）。

🔴 **新建文件也要归一**（2026-10-11 踩到）：用 `Write` 工具新建的 `.md` 是 **LF**，但 `协同/交接/WK-*.md` 约定是 **CRLF** —— 新建后必须按字节归一（`raw.replace(b"\n", CRLF)`）再交付，否则后续脚本里的「纯 CRLF 断言」会当场挡下。

- 🔴 **`--create` 有静默覆盖风险（2026-10-13 复核）**：任务 ID 已被**别的会话**占用时，脚本**不报错**，而静默走「更新」分支 → **覆盖他人台账行** + 追加错配的会话索引行。台账变更记录里 2026-10-02 已有**两次同源前科**（16:15 / 16:24 两条）。→ **并行会话多发时段（同一任务被两个对话框同时推进）先用 `--dry-run` 看它打算写什么**，确认确实在「新建」再真写；`--create` 报出的任务号要回台账 grep 一遍确认此前不存在。
- **`--files` 是并集语义**：同一任务重复收工不会丢之前的产出路径。
- **`--dry-run` 先看它打算写什么**，再真写。
- ⚠️ **禁用手写 `Write`/`Edit` 直改这三处**：`Write` 产出 LF（§四 已述）、`Edit` 会把混合行尾的文件静默归一为 LF。
