# 平台规则补齐（ops-platform-rules-onboarding）

> 为什么有这份：2026-10-11 给抖音 / 视频号 / B站 补齐「反搬运 ＋ AI 声明」规则时，发现三件事都要重新推——
> ① 原文该落 `_规则原文/` 还是 `规则与合规/`（**用户口述与 vault 规范不一致**）；② 行尾基准；
> ③ 一处改动要在 **N 处**登记。这份把动作和坑一次固化。

## 一、动手前（不许跳）

```bash
python C:\Users\Administrator\Documents\code-news\scripts\work_lookup.py "<平台/主题关键词>"   # 开工三查
python C:/Users/Administrator/Documents/code-news/scripts/tool_inventory.py <关键词>          # 复用盘点
```

**必读口径文档（唯一权威，别凭印象）**：
- `运营中心/_索引.md` —— 目录结构与归类口径
- `运营中心/_加工与应用规范.md` —— 规则卡模板 / 验证状态 / 应用机制
- `运营中心/_地图.md` —— 内容地图（也是要改的登记之一）

## 二、两层落点（最容易落错的地方）

用户可能说「落到 `规则与合规/`」，但 vault 规范里这是**两层**：

| 内容 | 落点 | 形态 |
|---|---|---|
| **平台官方原文** | `运营中心/<平台>/_规则原文/` | 主题化命名，**无 frontmatter**：`# 标题` ＋ `> 来源/状态` ＋ 分节 ＋ `## 相关文档` 双链 ＋ 底部 `*来源*` |
| **规则卡（加工产物）** | `运营中心/<平台>/规则与合规/` | **有 frontmatter**（类型=规则卡…），正文 `触发/动作/边界/自检` |
| 跨平台通用法规 | `运营中心/通用/_规则原文/` | 同原文层 |

**判据**：`规则与合规/` 只放「动作单 / 自查单」形态的规则卡；**原文一律进 `_规则原文/`**。
→ 用户说「落到规则与合规」时，**两层都落**：原文进 `_规则原文/`，提炼的动作单进 `规则与合规/`。**并说明为什么这么分。**

**命名对齐现有标准件**：图文平台（公众号 / 头条 / 知乎 / 小红书）已有标准件命名 ——
`AI声明与原创度要求.md`、`发布规则.md`、`限流原因排查.md`、`违禁词清单.md`、`推荐算法与流量池.md`、`标题高点击公式.md`。
视频平台补齐时**沿用同名**（跨目录同名是**设计使然**，不是歧义；引用时带路径即可）。

## 三、行尾基准（新建文件必读字节，别猜）

| 目录 | 基准（2026-10-11 实测） |
|---|---|
| `运营中心/<平台>/_规则原文/` | **CRLF**（小红书 12 / 头条 7 / 知乎 7 / 公众号 5 全部 CRLF） |
| `运营中心/<平台>/规则与合规/` | **CRLF 多数**（公众号 6 张里 4 张 CRLF） |
| `运营中心/_地图.md` | **纯 LF** |
| `运营中心/_索引.md`、`_加工与应用规范.md` | **纯 LF** |

**做法**：`Write` 产出后，用 Python **按字节**把新文件归一到 CRLF；改 LF 文件时用字节级替换并自证「只动行尾、内容一字不动」。
⚠️ **别用 `Edit` 改 MIXED 文件**（会被静默归一为 LF）；**别用 `grep` 判行尾**（Git Bash 下对纯 LF 文件也报「全部含 CR」）。

## 四、抓官方原文的手法

1. **官方域名优先**：平台规则中心 / 官方公告 / 国家法规原文（如 `cac.gov.cn`、`gov.cn`、`douyin.com/rule/`）。
   第三方解读（知乎 / 头条 / CSDN）**只能作辅助**，且必须标注。
2. 🔴 **必须区分「官方条款」与「行业实践」并显式标注**：
   - 官方条款 → 直接引原文措辞，注明出处 URL；
   - 行业实践（如「跨平台五维指纹查重」这类分发工具 / 自媒体的总结）→ **必须写明「非平台官方条款，只作参考，不得当硬规则」**，并在规则卡 `边界` 里重申。
   - 教训：把行业实践当官方条款写进 vault，就是**教坏智能体**（`_加工与应用规范` §三 原话）。
3. **拿不到就如实写「原文未涉及」**，不要用推测填空。
   （例：抖音 AI 标识一周年公告**未披露**处罚梯度 → 明写「未披露，需查专项规则」。）
4. 有价值的一手线索常在 **vault 已有的 `_原文/`** 里（如 `视频号/_原文/2026-10-01_视频号10月新规…`）——
   但那是**博主讲的**，不是官方原文，只能当辅助来源。

## 五、规则卡模板与验证状态

```markdown
---
类型: 规则卡
平台: <平台>
叶子: 规则与合规
标题: "..."
验证状态: 信号
来源:
  - "运营中心/<平台>/_规则原文/<文件>.md"     # 用完整路径字符串，不用双链（避同名歧义）
最后更新: YYYY-MM-DD
生成: 人工
---

## 触发
任务型 + 症状型各写一行（没有触发就不写这张卡）。

## 动作
可直接执行的做法，写「做什么」，不写「要重视」。

## 边界
平台红线 + 冲突时以谁为准 + 「官方条款 vs 行业实践」的分层说明。

## 自检
可勾选验证项。
```

**验证状态怎么填**：平台**官方明文**是「规则本身」而非经验，依据够硬 —— 但**未经我方实战验证**时**仍填 `信号`**，
并在 `边界` 写明「依据＝官方明文 ＋ 国家级法规，非博主经验；未经实战验证，故记信号」。
跑过一次带数据的实战后按回流机制（`ops_card_feedback.py`）评估升 `基因`。

## 六、同步登记清单（一处改动要在 N 处登记）

补了 `_规则原文/` 后，至少改这两份，**每份有多个落点**：

**`运营中心/_地图.md`（LF）**：
1. §二 平台表的该平台行（机制原文篇数、规则卡数、备注）
2. §二 合计行（规则卡 / 机制原文总数）
3. §三 症状排查表注释（「其余平台无 `_规则原文` 可依」）
4. §四「平台机制（N 篇 `_规则原文`）」
5. §五 缺口记录（「XX 平台没有 `_规则原文`」）

**`运营中心/_加工与应用规范.md`（LF）**：
6. §4.1 症状排查表注释
7. §八 落地状态表「症状排查表」行

**动手前先 `Grep` 找全登记点**（别漏）：
`没有 \`_规则原文\`|无 \`_规则原文\`|暂无 \`_规则原文\`|平台机制原文|未建（不编）`

## 八、踩坑集（实测踩过的）

| 坑 | 现象 | 正解 |
|---|---|---|
| **落点按口述而非规范** | 用户说「落到 `规则与合规/`」就照做 → 原文堆进规则卡层，破坏「一层只装一类」 | 先读 `_索引.md` 定口径：原文→`_规则原文/`，卡→`规则与合规/`；**两层都落并说明** |
| **把行业实践当官方条款** | 把分发工具总结的「五维指纹」直接写成平台规则 | 显式标注「非官方条款，只作参考」，规则卡 `边界` 重申 |
| **跨目录同名当歧义** | `AI声明与原创度要求.md` 在 4＋ 平台目录同名，误以为要改名 | 同名是标准件的**设计使然**（`obsidian-vault-ops` §十·补「同名≠歧义」）；**引用一律带路径**，`来源` 用完整路径字符串不用双链 |
| **用 `Edit` 改 LF 治理文档** | `_地图.md` 多处编辑，`Edit` 可能漏改/归一 | 同文件 ≥3 处改动 → 用「Python 读字节 → 锚点断言 `count==1` → 字节替换 → 按原行尾写回 → 复读自证」 |
| **锚点写转义序列** | `b"...\r\n..."` 经 `Write` 规范化 → 断言恒 0 | 锚点含 CR/LF 一律**运行时构造**（`bytes([13,10])`）；本流程文件多为纯 LF，直接写 `\n` |
| **新文件行尾随 `Write`** | `Write` 产出 LF，与 `_规则原文/` 的 CRLF 基准不符 | 写完立刻按字节归一，断言 `crlf==nl and lone==0` |
| **只改地图不改规范** | `_地图.md` 改了，`_加工与应用规范.md` §八 仍写「无 `_规则原文`」 | `Grep` 全扫登记点（§六），一次改全 |
| **抓网页拿不到正文** | 部分官方页是 JS 渲染（如抖音规则中心 H5、库库）→ `WebFetch` 返回空/导航 | 换官方镜像或同内容转载源（如 cnsa.cn 转载抖音公告）；或换搜索词找条款全文 |
