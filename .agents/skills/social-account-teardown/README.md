## 一个真实案例：粉丝差 20 倍，互动密度反而差 8 倍

拆了两个小红书 AI 赛道的对标号：一个 13.3 万粉的大 V，一个 6,506 粉的小号。
本来想看"大号为什么强"，数据指向了相反的问题。

```
  指标              数字生命卡兹克     EVI是个研究员      比值
  ──────────────────────────────────────────────────────────────
  粉丝              132,597           6,506              20.4 倍
  平均赞            856               339                2.5 倍
  中位赞            338               148                2.3 倍
  千粉均赞          6.45              52.1               8.08 倍  ← 关键
  头部占比 (Top5)   40.4%             58.3%
  日更频率          0.92 条/天        1.0 条/天          基本持平
  样本              92 条             30 条              都有统计意义
```

**剔除粉丝规模后，小号的单位粉丝互动是大号的 8 倍。**

不是 EVI 写得好到天上，是**受众精准**——他只做"拆小红书账号"，关注他的人
几乎全是同行和想学运营的人，**精准粉丝的互动密度天然高**。卡兹克做的是
泛 AI 内容，受众里有大量泛关注者，单条均赞自然被摊薄。

这就推翻了一个常见直觉：**先涨到几十万粉再变现**。EVI 用 6,506 个精准粉
已经支撑了"知识付费 + 咨询"的变现路径，简介里直接挂着"希望大家找我知识付费"。

> 上面所有数字带可靠性标注。如果你的号只有十几条、总赞几百，脚本会直接告诉你
> "百分比仅供参考"——不给你一个看起来很确定、其实是噪声的结论。

```
═══ 账号横向对比 ═══

  [体量]    粉丝 / 主页总赞 / 平均赞 / 中位赞 / 峰值赞 / 千粉均赞 / 总赞÷粉丝

──── 关键差异 ────
  ▍强差异（已通过可靠性门禁）   7 项
  ▍中等差异 / 待验证             1 项

──── 局限性（必读）────
  ⚠️ 粉丝量级差 20 倍：绝对点赞数不可直接比，请只看归一化指标
  ⚠️ 仅 5 条样本：所有百分比都是定性参考，不构成强结论
  ⚠️ 本脚本只给相关性，不给因果
```

| 抖音 | ✅ | ✅ | 小号需要 | 未登录上限约 18 条；小号一条都不给 |
| 小红书 | ✅ | ✅ | **必须** | 列表只给点赞数，评论/收藏需补单条详情 |
| B站 | ✅ | ⚠️ | 否 | 作品列表被 `-352` 风控挡，海外 IP 会加剧 |
| Instagram | ❌ | ❌ | 需要 | 匿名返回 429，未端到端验证 |
| 小红书蒲公英 | ⚠️ | ❌ | 必须 | **受限**：账号权限不足时自动降级到公开主页，不会硬抓 |

### 蒲公英为什么是 ⚠️ 不是 ✅

小红书蒲公英 (`pgy.xiaohongshu.com`) 的 `/api/solar/*` 接口**全部按调用方身份路由**，
错误路径返回 `"url not support"` 而不是 404，是设计上"假装不存在"。本工具的测试账号
命中 `blockBlogger: true, access: ["buyer"]`，所有 `/creator/*`、`/brand/*`、
`/agent/*` 路由都落到"你访问的页面不见了"。

实测结论：
- ✅ 你能从蒲公英拿到 `/api/solar/user/info`，得知**当前账号的可用身份和权限**
- ❌ 你不能从蒲公英拿到 EVI/卡兹克 的后台数据 —— 蒲公英的数据是按调用者隔离的，
  不存在公开数据接口；SEO landing URL 也会被前端跳到"页面不见"
- ✅ 作为**降级**，工具会自动切回 `fetch_xhs.js + fetch_xhs_detail.js`，抓对方
  公开主页 —— 这是不登录对方账号能拿到的最全数据

要拿到蒲公英后台数据（报价档位、商单数、近 30 天互动率、粉丝画像），目前没有
  合规路径：要么用第三方付费工具（新榜、千瓜、灰豚），要么拿到对应账号本人的
  蒲公英 cookie —— 都不在 skill 覆盖范围。

## 为什么数字可信

拆解工具最危险的不是抓不到数据，是**给你一份看起来很确定、其实全是噪声的报告**。六道防线：

1. **量级门禁** — 总赞 <1000 时，百分比强制降级并标注"不可作决策依据"
2. **抓取覆盖度** — 只抓到 18/85 条时会明说"这不是全部作品"
3. **缺失字段置 null 而非 0** — 拿不到就显示 `N/A`，绝不当 0 参与比较
4. **置换检验 + BH 校正** — 爆款因子用 2000 次重采样算 p 值并做多重比较校正
   （实测救回过假阳性：某账号"周日发布" p=0.02 → p_adj=0.09，降为弱信号）
5. **混杂变量控制** — 单独检验内容年龄，避免把"发得早"误读成"有什么特征"
6. **同批作品对比** — 趋势里总赞增长和老内容增长分开算，不把"多发了几条"当成"内容在涨"

**抓不到就明说抓不到，不用同类语料脑补。**

```
L1 抓取层（按平台适配）  →  L2 归一化  →  L3 指标/对比/爆款/趋势
   fetch_douyin.js           统一 schema      全部复用同一套口径
   fetch_xhs.js              posts.json       （core.js 是唯一事实来源）
   fetch_bilibili.js
   fetch_instagram.js
   fetch_pgy.js (受限)
```

换平台只需加一个 `fetch_*.js`，下游完全不动。
